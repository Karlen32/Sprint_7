# Sprint_7

Автотесты для API сервиса доставки самокатов.

## Структура проекта

## Установка

```bash
pip install -r requirements.txt
```

## Запуск тестов

```bash
# Запуск всех тестов
pytest

# Запуск с генерацией Allure отчетов
pytest --alluredir=target/allure-results
```

## Тесты

- **test_create_courier.py** - тесты создания курьера
- **test_login_courier.py** - тесты авторизации курьера
- **test_delete_courier.py** - тесты удаления курьера
- **test_create_order.py** - тесты создания заказа
- **test_get_order_by_track.py** - тесты получения заказа по трек-номеру
- **test_accept_order.py** - тесты принятия заказа курьером
- **test_orders_list.py** - тесты получения списка заказов


# Баги

## Баг: Некорректный текст ошибки при регистрации с уже существующим логином

**Ожидаемый результат:** 
Сервер возвращает код 409 и сообщение:
«Этот логин уже используется»

**Фактический результат:**
Сервер возвращает код 409, но текст сообщения отличается от спецификации:
«Этот логин уже используется. Попробуйте другой.»


## Баг: При авторизации без пароля возвращается 504 вместо 400

**Ожидаемый результат:**
Сервер должен вернуть HTTP 400 Bad Request и тело:
`"message": "Недостаточно данных для входа"`

**Фактический результат:**
Сервер возвращает `HTTP 504 Gateway Timeout.`
Ответ об ошибке отсутствует или сервис недоступен

## Баг: При удалении курьера без ID возвращается 404 вместо 400

**Ожидаемый результат:**
Сервер возвращает:
`HTTP/1.1 400 Bad Request`
`"message": "Недостаточно данных для удаления курьера"`

**Фактический результат:**
Сервер возвращает:
`HTTP/1.1 404 Not Found`
`"message": "Not Found."`

## Баг: Сообщение ошибки для удаления несуществующего курьера отличается от ожидаемого

**Ожидаемый результат:**
Сервер возвращает сообщение:
`"Курьера с таким id нет"`

**Фактический результат:**
Сервер возвращает сообщение:
`"Курьера с таким id нет."`

## Баг: API не принимает заказ при корректных данных — возвращает 404 вместо 200

**Ожидаемый результат:**
`HTTP/1.1 200 OK`
`"ok": true`

**Фактический результат:**
`HTTP/1.1 404 Not Found`
`"message": "Заказа с таким id не существует"`

## Баг: API возвращает 404 вместо 400 при попытке принять заказ без передачи номера заказа

**Ожидаемый результат:**
`HTTP/1.1 400 Bad Request`
`"message": "Недостаточно данных для поиска"`

API должно валидировать отсутствие обязательного параметра и вернуть 400.

**Фактический результат:**
`HTTP/1.1 404 Not Found`
`"message": "Not Found."`

## Баг: Невозможно протестировать повторное принятие заказа, т.к. API не принимает заказ даже при валидных данных
